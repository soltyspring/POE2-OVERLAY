# 라벨별 OCR 구현과 검증

## 평가 데이터

`test/fixtures/ocr-ground-truth.json`에 대화에서 제공된 19장과 이름·수량·정규화 위치를 기록했다.
두 장은 오버레이 UI만 있는 부정 사례이며 바닥 아이템 검출의 정답은 0개다.
라벨 위치는 이미지에서 수동으로 읽은 대략적인 사각형이다. 경계 픽셀 정답은 아니며
예측 OCR 시작 위치가 사각형 안에 있는지 12px 허용 오차로 평가한다.
희귀 이름+베이스는 두 줄 전체가 맞아야 정답으로 센다. 베이스만 읽힌 결과는 별도 오탐/누락으로 드러난다.
같은 이름의 여러 라벨도 서로 다른 위치의 정답으로 관리한다.

실행: `electron scripts/evaluate-ocr.cjs <결과폴더> [이미지폴더]`
이미지는 codex-clipboard-<id>.png로 찾으며 저장소에 사용자 스크린샷을 복사하지 않는다.
없어진 임시 파일은 실패 항목으로 기록한다. 생성 BMP는 처리 뒤 삭제한다.
이름/수량 정확한 라벨 수, 누락, 오탐, precision/recall, OCR 시간, CPU 시간,
워커 응답 RSS, 처리 픽셀 수, 재시도 수를 기록한다.
RSS는 응답 시점 측정이며 전체 앱 RAM 또는 지속 샘플링한 최대 RAM이 아니다.

## 시험 경로

`POE_OCR_LABEL_PIPELINE=1`로 실행하면 활성 필터 팔레트를 읽고 라벨별 경로를 사용한다.
기본 경로는 유지했다. 새 경로의 현재 정확도가 충분하지 않기 때문이다.

- 평평한 배경과 세로 경계로 라벨 사각형을 찾고 글자 기반 후보로 보완한다.
- 밝은 배경은 원본을 유지하고 어두운 배경은 글자 대비를 보정한다.
- 작은 영역만 시트로 모아 확대 인식한다. 시트 크기는 OCR 허용 크기로 제한한다.
- DB 매칭에 실패한 영역만 최대 4개 재시도한다. 전체 화면 추가 OCR은 하지 않는다.
- 시트 줄이 라벨 경계를 넘으면 제외한다. 줄에 regionId를 부여해 다른 라벨끼리 이름/베이스를 합치지 않는다.
- 사용자 필터의 글자·배경·테두리·크기를 파싱한다. 배경/크기 힌트는 추출했으나 검출 임계값 조정에는 아직 반영하지 않았다.

## 검증 결과와 남은 작업

15장/51라벨의 첫 비교에서 기존 방식은 45라벨, 새 방식은 21라벨이 정확했다.
검출·확대 개선 후 같은 15장에서 새 방식은 30라벨로 늘었다.
새 방식은 그 비교에서 OCR CPU 시간 합계 785ms, 기존은 922ms였으나
검출 CPU는 포함되지 않았고 워커 캐시/첫 실행 영향도 있어 앱 CPU 감소율로 해석하면 안 된다.
17장/103라벨 최종 비교 결과는 %TEMP%/poe2-label-final-verified/results.json에 있다.
기본 전체 화면 OCR은 76라벨, 새 라벨 경로는 41라벨이 이름/수량/위치까지 일치했다.
baseline은 단일 전체 화면 OCR이며 현재 기본 앱의 원본 보완/영역 재시도까지 포함한 경로가 아니다.

지금의 병목은 OCR 엔진보다 검출 누락과 게임 효과에 연결된 후보 영역이다.
겹친 라벨 분리, 배경색/폰트 크기 힌트 반영, 위치 주석 검수 후 재평가가 필요하다.
새 경로가 기존을 넘기 전에는 기본으로 승격하거나 엔진을 선정하지 않는다.
RapidOCR 비교는 같은 검출 영역을 사용해 실행할 수 있지만 이 단계에서는 선정하지 않았다.
