# OCR·시세 지연 검증 (2026-10-05)

사용자가 첨부한 710×681 화폐 보상 이미지와 696×758 젬 보상 이미지를 실제 Windows OCR 및 RapidOCR로 각각 4회 처리했습니다. 첫 실행은 엔진 초기화/모델 다운로드가 포함되어 별도로 봅니다. 전체 게임 화면·캡처·Electron UI 성능 측정은 아닙니다.

| 엔진 | 초기화 뒤 OCR 시간 | 측정 OCR 프로세스 메모리 | 결과 |
|---|---|---|---|
| Windows 한국어 OCR 상주 프로세스 | 106~227ms | 약 114~121MB | 두 이미지 보상 이름 인식, 1x 오독은 수량 접두부 보정 필요 |
| RapidOCR 3.9.2 + ONNX Runtime, 한국어 PP-OCRv5 mobile 인식 / v4 mobile 탐지 | 1,267~1,564ms | 약 141~168MB | 두 이미지 보상 이름과 1x를 읽음, 룬 아이콘의 잡음이 더 적음 |

메모리는 네 번 실행 중 관측한 작업 집합/RSS이며 최대치나 장시간 안정 상태를 뜻하지 않습니다. OS 서비스·Electron·캡처·게임의 메모리는 제외됩니다. Windows 작업 집합과 Python RSS는 구현별 측정치로 완전히 동일한 메모리 지표라고 단정하지 않습니다.

워커의 CPU 시간은 재실행 기준 Windows 약 78~188ms, RapidOCR 약 1,688~2,219ms였습니다. 매 3초 실행하면 단일 CPU 코어 시간으로 각각 약 2.6~6.3%, 56~74%에 해당하는 단순 계산입니다. 작업 관리자의 전체 CPU 사용률은 논리 코어 수·캡처·게임 부하에 따라 다르고, OCR 서비스에서 사용한 별도 CPU 시간은 이 계산에 포함되지 않을 수 있습니다. GPU를 지정하지 않았으며 RapidOCR은 CPU/ONNX 경로를 사용합니다.

RapidOCR은 [공식 모델 목록](https://rapidai.github.io/RapidOCRDocs/main/model_list/)에 한국어 mobile 모델을 제공합니다. [PaddleOCR의 모델 설명](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/module_usage/text_recognition.en.md)의 모델 크기/행 단위 추론 지표는 우리 화면 전체 처리 시간이나 실제 메모리 크기와 같지 않습니다. 이번 선택은 공식 표보다 첨부 화면 실측을 우선했습니다.

## 적용

- 속도·자원 사용을 우선해 기본은 Windows OCR입니다. Python 가상환경을 설치하고 `POE_OCR_ENGINE=rapidocr`를 설정하면 오픈소스 RapidOCR을 사용합니다.
- 매 스캔마다 프로세스/모델을 새로 시작하지 않습니다. 오류·시간 초과 시 작업을 해제하고 이후 재시도가 가능하게 합니다.
- 완전히 같은 캡처 PNG는 이전 OCR 결과를 재사용합니다. 게임 화면 전체가 움직이면 이 최적화 효과는 작습니다.
- OCR과 시세 데이터를 동시에 기다립니다. 화폐/보상 결과를 먼저 표시하고 상세 매물 결과를 추가합니다.
- 3초 자동 스캔은 진행 중인 작업을 건너뛰며 요청을 쌓지 않습니다. 화폐/소모품 집계 시세와 최근 상세 검색 캐시가 대상입니다. 새로운 고유/젬 상세 검색은 F6으로 실행합니다. 서버 장애/첫 초기화로 작업이 3초를 넘으면 실제 간격도 길어집니다.
- 사용자의 서버 URL을 기본 연결로 설정했습니다. `Forbidden Rites`에서 서버 시세 654개 조회에 약 858ms가 걸렸습니다. 이는 단일 측정으로 네트워크 지연 보장이 아닙니다.

재현: `node scripts/ocr-benchmark.cjs <image.png>`, `node scripts/pipeline-benchmark.cjs <image.png> "Forbidden Rites"`. 결과의 `run:0`은 초기 실행입니다. 실제 전체 모니터 캡처와 GUI 동작은 현재 실행 환경의 `UnknownVizError` 때문에 확인하지 못했으므로 3초 주기의 실게임 부하·오인식률은 추가 검증이 필요합니다.

실서버+화폐 보상 이미지의 병렬 파이프라인도 실행했습니다. 초기 실행은 2,833ms, 이후 OCR+사전 대응+시세 캐시 조회는 168ms/151ms였고 보상 6행 모두 가격을 연결했습니다. 이 시간에는 실제 모니터 캡처·GUI 표시·장비 거래 API 요청은 포함되지 않습니다.
