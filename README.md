# POE2-OVERLAY

한국어 PoE2 바닥 아이템을 화면에서 읽고 엑잘 기준으로 정렬하는 **Windows 초기 프로토타입**입니다.

## 실행

Windows 10/11, Node.js 22 이상, Windows 한국어 OCR 언어 기능이 필요합니다.

```powershell
npm install
npm start
```

1. PoE2를 창/테두리 없는 창 모드로 열고 바닥 라벨을 표시합니다.
2. 앱에서 사용하는 리그의 정확한 이름을 입력합니다. 기본은 `Standard`입니다.
3. **F6**: 마우스가 있는 모니터 전체를 한 번 캡처하고 한국어 OCR → 사전 일치 → 시세 조회 → 정렬합니다. 게임 모니터에 마우스를 두세요. 오버레이는 Windows 화면 캡처 제외 기능으로 제외하며 스캔할 때 창을 숨기지 않습니다. Windows 10 2004 이상/11을 권장합니다.
4. **F8**: 패널 표시/숨기기. 앱이 게임의 라벨 표시 키를 대신 누르지 않습니다.
5. 판매 전에는 게임에서 아이템을 **Ctrl+C**로 복사한 후 **복사한 아이템 조회**를 누릅니다.

첫 조회는 사전과 여러 가격 분류를 받으므로 시간이 걸립니다. 캡처는 로컬 임시 디렉터리에만 저장하고 스캔이 끝나면 삭제합니다. 게임 메모리 접근이나 주입은 없습니다.

## 구현 범위

- 모니터 전체 OCR 텍스트·좌표. 공식 한국어 사전과 정확히 일치하는 이름만 사용합니다. 게임 외 텍스트도 인식 대상이므로 게임을 전체 화면으로 표시하는 것이 좋습니다.
- 화폐·일부 소모품: 공식 static ID와 poe.ninja ID 연결. `3 x 이름` 또는 `이름 x3` 수량을 곱합니다.
- 엑잘 환산: `core.primary`와 `core.rates` 사용. 리그 기준 화폐가 엑잘인 경우도 처리합니다.
- 고유 이름이 보이면 이름 기준 공식 매물 최대 10개를 조회하고 환산 가능한 매물의 **최저가**로 정렬합니다. 옵션을 확인하지 못한 상태의 참고값이며 전체 시장 최저가를 보장하지 않습니다. 한 스캔당 고유 최대 5종.
- 고유 베이스 이름만 보이면 같은 베이스의 고유 매물을 검색하고 **조회한 매물 중 후보 최저가**를 표시합니다. 후보 이름을 함께 보여 주며 실제 드랍 종류·옵션은 확정하지 않습니다. 최대 10개 중 환산 가능한 매물 기준이므로 전체 시장 최저가를 보장하지 않습니다. 주황색 판별 전에는 일반/마법 장비 베이스도 같은 참고값이 나타날 수 있습니다. 희귀 이름만으로는 가격을 붙이지 않습니다.
- 복사한 한국어 옵션: 공식 사전에서 정확하고 유일하게 대응되는 **단일 수치**를 동일 값의 최솟값·최댓값으로 검색합니다. 대응하지 못한 수치 줄은 결과에 표시합니다.
- `(implicit)` 등 그룹 표기가 있으면 해당 그룹을 사용하며, 표기가 없으면 명시 옵션으로 처리합니다. 그룹이 빠진 복사 텍스트는 검색 조건을 공식 사이트에서 확인해야 합니다.
- 요청 직렬화, 최소 간격, 서버 제한 헤더와 HTTP 429 대기, 15분 가격 캐시, 1분 매물 검색 캐시.
- 상시 위 패널과 공식 검색 결과 링크.

## 한계와 후속 작업

실제 게임 화면 인식률은 아직 검증하지 않았습니다. 일반 Windows OCR과 2400×1350 이내 캡처이므로 작은 글씨·4K·HDR·라벨 겹침에서 오독할 수 있습니다. 주황색 영역 분리, 한국어 퍼지 매칭, 툴팁 OCR 옵션 파싱, 원래 화면 좌표 복원, 클릭 통과, 게임 포커스에 따른 숨김, 사용자 지정 단축키, 설정 저장, 설치 파일은 후속 작업입니다.

공식 검색은 로그인/서버 정책에 따라 실패할 수 있습니다. 로그인 쿠키 저장이나 인증 우회는 없습니다. 현재 온라인 매물 기준이며 즉시 구매 시장 선택 UI는 후속 작업입니다. 희귀 옵션 검색은 DPS·범위값·타락·품질·소켓을 모두 반영하는 완성된 평가기가 아닙니다.

젬처럼 레벨이 중요한 물품은 전체 이름이 일치하지 않으면 가격화하지 않습니다. 시세가 없을 때 다른 물품 가격으로 대체하지 않습니다. 캐시는 메모리 안에서만 유지됩니다. 매물·집계 시세는 실제 판매가와 다를 수 있습니다.

## 검증

```powershell
npm test
npm run check
node scripts/market-smoke.cjs
node_modules/.bin/electron.cmd . --smoke-test
```

핵심 테스트는 환산, 수량, 위치별 중복, 고유 후보, 옵션 검색, 미확인 장비를 다룹니다. market smoke는 실제 Standard 시세 연결을 검사합니다. UI smoke는 패널/격리된 preload를 확인하고 임시 디렉터리에 PNG를 저장한 뒤 종료합니다.

소스 분석과 설계 판단: [6개 저장소 분석 보고서](docs/repository-analysis.ko.md).

현재 개발 환경에서 GUI 실행은 `UnknownVizError`로 실패해 확인하지 못했습니다. 한국어 OCR 샘플·실제 가격 API·핵심 테스트 6개·구문 검사까지 통과한 상태이며, 실제 게임에서의 작동은 후속 검증이 필요합니다.

## 룬 조합 보상 목록

첨부 예시처럼 `3x 상위 제왕의 오브`, `3x 상위 카오스 오브`, `3x 상위 엑잘티드 오브` 등의 보상 목록도 F6으로 읽습니다. 총 가치는 수량 × 개당 집계 시세입니다. `1x`를 `lx` 또는 `1)(`로 읽는 Windows OCR 오독을 수량 접두부에 한정해 보정합니다. 이름과 상위 등급은 공식 사전과 정확히 일치해야 하며, 일반 오브 가격으로 대체하지 않습니다. 같은 보상의 1개/3개 행은 따로 유지합니다. 룬 아이콘 조합 자체를 해석하거나 조합을 추천하는 기능은 포함하지 않습니다.

첨부 이미지 재검증: `node scripts/runeshape-smoke.cjs <이미지.png> [리그]`. 이 스크립트는 예시의 보상 6행에 특화된 검사입니다.

첨부 화면에서 실제 OCR → 공식 한국어 ID → Standard 시세 → 수량 환산을 실행해 6개 보상 행을 모두 가격화했습니다. 총 13개 회귀 테스트도 통과했습니다. 시세는 선택한 리그와 조회 시점에 따라 달라집니다. 게임 전체 모니터를 캡처한 해상도에서도 같은 인식률을 보장하는 결과는 아닙니다.

## 창 안정성 보강

클릭/스캔 때 창을 숨기는 동작을 제거했습니다. 창이 표시되거나 포커스를 받으면 최상위·클릭 가능 상태를 다시 적용하고 최소화 버튼을 비활성화합니다. F8로 명시적으로 숨긴 창은 비동기 조회가 끝나도 다시 나타나지 않습니다. 중복 실행은 기존 창을 열며, 조회 중에는 스캔·옵션 조회·리그 변경을 잠급니다. 조회 시작 시 리그와 클립보드 정보를 고정하고 임시 파일 정리 실패가 다음 조회를 막지 않도록 처리합니다. UI 프로세스 종료 시 최대 두 번 다시 로드합니다. 창 상태 회귀 테스트를 포함해 총 11개 테스트가 통과했습니다. 실제 게임 위 포커스/클릭 검증은 별도로 필요합니다.
